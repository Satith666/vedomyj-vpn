# Инструкция для нейросети: как дорабатывать «VEDOMYJ VPN»

Этот файл — для ИИ-ассистента (Claude, ChatGPT и др.), которому владелец присылает программу, чтобы что-то исправить или добавить. Прочитай его целиком перед изменениями.

## Как начать новый чат (для владельца)

1. Приложи к чату архив `VedomyjVPN-<версия>-source.zip` (или папку программы без `data`) и этот файл.
2. Если что-то сломалось, приложи текст из «Журнала ошибок» (на ПК «Ещё → Журнал ошибок → Скопировать текст заявки», на телефоне «Настройки → Журнал ошибок») или заявку с GitHub. Или отчёт: жёлтый значок «!» в программе → «Скопировать отчёт для нейросети», или «Настройки → Проверка программы → Показать файл отчёта», или файл из `data/reports/`. На телефоне: «Настройки → Проверка программы → Отправить файл отчёта».
3. Напиши, что нужно. Например: «Вот программа VEDOMYJ VPN и отчёт об ошибке. Прочитай AI_GUIDE.md и исправь проблему».

**Никогда не отправляй папку `data`** — там ссылки на подписки и настройки.

## Что это за программа

VEDOMYJ VPN — клиент VPN для Windows (и приложение для Android в папке `android/`, см. раздел «Android: как устроено») поверх ядра [Xray](https://github.com/XTLS/Xray-core). Пользователь в России. Главная цель — **всё настраивается само и работает лучшим образом**:

- загружает подписки (как Happ), проверяет пинг и скорость серверов, подключается к лучшему;
- **российские сайты всегда идут напрямую** (многие не открываются с зарубежных IP), заблокированные — через VPN;
- Автопереход (в коде — autopilot): при зависании сервера быстро переключается на запасной, без перезапуска (замена outbound через API ядра);
- «Проверить сайт»: пользователь вставляет адрес, программа проверяет его напрямую и через VPN и сама добавляет правило;
- аккуратное автообновление: серверы, списки сайтов и ядро — по своему расписанию, по одному, без разрыва связи;
- режим TUN (весь трафик компьютера) с выбором движка: Xray TUN, sing-box, tun2proxy или «Авто»; защита от утечек, шифрование DNS, блокировка рекламы;
- обход замедлений YouTube и Discord без VPN: zapret и ByeDPI с автоподбором стратегии, один основной, второй запасной;
- «Поделиться»: файл настроек (перенос на другой компьютер) и QR-коды для телефона;
- Мультисервер (сервис, закрытый на основном сервере, идёт через другой), маскировка (дробление TLS для серверов, которые режет провайдер), обход белых списков (сам замечает и переключается);
- работа в фоне со значком у часов, доступ из домашней сети с логином и паролем, раздача VPN по Wi-Fi;
- проверяет популярные сервисы (Telegram, Discord, YouTube, ChatGPT, Госуслуги…) и сам чинит маршруты;
- жёлтый значок «!» показывает, если программа не справляется с какой-то обязанностью.

## Название

Программа называется **VEDOMYJ VPN** (читается «ведомый»), значок — буква V из белой и янтарной линии (`ui/icons/monogram.svg`, `ui/icons/app.ico`, на Android — `res/drawable/ic_launcher_fg.xml`). Раньше она называлась Pult VPN, и внутренние имена остались прежними: папка кода `pult/`, пакет `com.pultvpn.app` и мост `window.Pult` на Android, метки `PULT_*` в скрипте своего сервера, формат файла настроек `pult-vpn-settings`. **Их не переименовывай** — сломается совместимость со старыми файлами настроек и между версиями. Старая запись автозапуска `PultVPN` убирается сама (`autostart.OLD_VALUES`).

## Как запускается

- `VedomyjVPN.exe` (в сборках) или `start.bat` → `main.py`: поднимает локальный сервер интерфейса на `127.0.0.1` со случайным портом и токеном (записывает их в `data/ui.json`) и открывает его в Edge в режиме приложения. Закрытие окна при включённой «Работе в фоне» оставляет программу у часов; иначе через 12 с программа завершается и отключает VPN.
- Трафик идёт через **системный прокси Windows** (HTTP-вход Xray) или, в режиме TUN, через виртуальный адаптер. Игры прокси не используют и идут напрямую.
- Зависимостей нет: **только стандартная библиотека Python 3.10+**. Не добавляй пакеты из pip — в сборках лежит «встроенный» Python с python.org без pip.
- Ядро Xray, zapret, ByeDPI, движки TUN и списки сайтов скачиваются с GitHub в папку `bin/`.

## Правила при изменениях

1. **После любых изменений запусти `python -m pult.selftest`** — все тесты должны пройти. Для новой функции добавь тест в `pult/selftest.py` (декоратор `@case("…")`).
2. **Тексты.** В коде сообщения пишутся по-русски, простым языком, без технического жаргона. Для каждой новой фразы движка добавь английский вариант в `pult/i18n.py` (`RULES`); для интерфейса — ключ в оба словаря `ui/i18n.js`. Самопроверка сообщит о фразах без перевода.
3. **Интерфейс.** Политика безопасности страницы запрещает встроенные скрипты и `onclick=` — только обработчики в `app.js` (делегирование по `data-act`, `data-nav` и т.п.). Длинные пояснения прячь под «Подробнее» (функция `details()`). Новое действие = функция в `ACTIONS` (app.js) + ветка в `dispatch` (webui.py).
4. **Долгие операции** запускай через `engine.run_task(title, func)`: одна задача за раз, полоса занятости, кнопка «Стоп». Внутри длинных циклов вызывай `self.check_stop()`. Заголовок задачи должен начинаться со слова из `Engine._busy_kind`, чтобы на нужной кнопке появилось «Остановить».
5. **Сбои важных обязанностей** (нет связи, ядро упало, подписка не обновляется, прокси перехвачен…) отмечай через `engine.problem(key, title, detail, where, fix)` и снимай через `engine.resolve(key)`. Так пользователь увидит жёлтый значок с объяснением.
6. **Безопасность и приватность.** Никогда не пиши в журнал и отчёты ссылки подписок, UUID, ключи. Интерфейс слушает только `127.0.0.1`. Не отключай проверку токена.
7. **Совместимость.** Цель — Windows 10/11, Python 3.10+. Пути могут содержать кириллицу (`C:\Users\Алекс\…`) — используй UTF-8 и `os.path`.
8. **Версия** — в `pult/__init__.py` (`APP_VERSION`) и `android/app/build.gradle` (`versionCode`, `versionName`). Повышай при выпуске и добавляй раздел `## <версия> — Android <версия>` в `CHANGELOG.md` (самопроверка это проверяет; текст уходит в описание выпуска и окно обновления через `build/changelog_notes.py`).
10. **Журнал ошибок.** Неожиданные исключения не глотай молча: в фоновых потоках — `if errorlog.is_bug(exc): self.errors.record_exc(exc, "где")` (Android: `recordBug(e, "где")`). Задачи `run_task`, действия интерфейса, монитор и необработанные исключения уже пишутся сами. Ничего секретного в `title`/`detail` класть не нужно, но `scrub` подстрахует.
9. **Ядро Xray.** Новые версии запрещают VLESS/Trojan без TLS к публичным адресам. Такие серверы помечаются `insecure` и запускаются совместимым ядром (`xray.LEGACY_VERSION`). При обновлении ядра проверяй, что конфиги принимаются (`xray run -test`).

## Автоматика: как устроено

- **Автоподбор для сайтов** (`engine.py`, раздел «автоподбор»): `_tail_access_log` → `_auto_offer` (новый адрес) → очередь → `_auto_probe`. Напрямую: `check_url`, затем `stall_test`; не работает напрямую, работает через VPN (порт `health`) → правило `proxy`; через VPN 403 → другие серверы во временном ядре → правило `server`. Правило добавляется на лету через API ядра (`ado` + `adrules -append`), иначе переподключение. Общие CDN (`SHARED_HOSTS`) — правило на сам адрес, а не на весь CDN. Хранится в `auto_sites`/`auto_seen`; свои правила главнее (`_auto_covered`).
- **Автоподбор в режиме «всё через VPN»:** `_auto_offer` берёт и адреса `proxy`; `_auto_probe` проверяет их только через VPN. Не соединилось → если подводит сам VPN (`_ping_failures`, `kill_on`) — ничего не решаем; иначе повтор, затем другие серверы (`_auto_other_server`, не больше `AUTO_HEAVY_PER_HOUR` временных ядер в час) → правило `server`. Ни через один → для самого сайта (не CDN и не поддомена) `_vpn_site_ask`: вопрос «напрямую?» (`vpn_suspects`, событие `vpn_site`, действие `vpn_site`, флаг `auto_ask_direct`). Напрямую сами не проверяем и не пускаем. Ответ «Напрямую» — свой маршрут `route_site(…, "direct")`.
- **«Проверить сайт»** — `check_site()`: блокировщик рекламы (кроме `threats`) → `ads_allow`; через VPN не открывается → другие серверы → напрямую (человек сам попросил). В результате `route` (`_site_choice`) — интерфейс показывает выбор пути (`route-select` с `data-site`).
- **«Сайт работает не полностью»** — `repair_site()`: `_host_log` (время, адрес, куда пошёл) → `_related_hosts(site)` (адреса за ±20 с от заходов на сайт) → `stall_test` по текущему пути → починка автоправилами; если адрес через VPN не качается ни через один сервер — проверка напрямую и «Всегда напрямую» (человек сам нажал кнопку; на Android — `repairFlow`, маршрут `direct`).
- **Порядок правил ядра** (`routing.build_rules`): частные сети → торренты (`protocol: bittorrent`, `torrent_route`) → свои сайты → свои списки → свои сервисы → реклама → **приложения** (`process`) → автоподбор → обход замедлений → Мультисервер → встроенные списки.
- Выключатели — `Engine.AUTO_FLAGS` (действие `auto_flags`, без переподключения), в интерфейсе — группа «Автоматика» в `FEATURES`.
- **Режим по умолчанию — «всё через VPN, российское напрямую»** (`mode: "vpn"`, `ru_direct`). Старый умный режим отправлял напрямую зарубежные CDN, которые провайдер не блокирует, а тормозит (замирание после ~16 КБ): сайт открывался, видео — нет. `_routing_migrate()` (флаг `routing_v2`) один раз переводит `smart` → `vpn`; потом выбор человека не трогается. Автоподбор и обход замедлений работают только в экономном режиме.
- **Проверка сервера под нагрузкой** (`_health_check`): если проверка связи не прошла, но через `proxy` идёт больше 50 КБ/с (`live["main_down"]` из `_poll_stats`), сервер считается живым; «медленно» не считается, пока через VPN идёт больше `BUSY_TRAFFIC` (300 КБ/с, `_vpn_busy`) — иначе Автопереход обрывал бы видео. На Android — `need = 4` неудачи при скорости больше 200 КБ/с. Скорость читается со страницы метрик ядра (`cfg["metrics"]`, порт `ports["metrics"]`, `xray.query_metrics` → `/debug/vars` по HTTP, без запуска процессов): каждые 2 с при открытом окне, раз в 5 с без него; ядро без метрик (`METRICS_GIVE_UP` неудач подряд) — по-старому `xray api statsquery` (2/10 с). Монитор — `_monitor_tick(tick)` (самопроверка «прокручивает» 10 минут: `t_quiet_background` считает запуски процессов — должно быть 0). Проверка связи — `_health_tick`: раз в `HEALTH_EVERY` (20 с) одним запросом в своём потоке, после неудачи — через `HEALTH_RECHECK` (5 с); пропускается, если за `HEALTH_RX_FRESH` (10 с) с сервера пришли данные (`_rx_at`) и пинг свежее минуты. Окно: на событие `live` обновляются только `#heroStats` и класс `.power` (`updateHeroLive`), герой пересобирается, только если изменилась разметка (`box._html`).
- **Мгновенное переключение** (`failover`): в конфиг добавляется запасной сервер `bk1`, правила «через VPN» ведут в балансировщик `failover` (`balancerTag`), `burstObservatory` следит за `proxy` и `bk1`; `fallbackTag` — основной. Служебные выходы переименованы через `@` (`mask@proxy`), чтобы префиксы балансировщика их не цепляли; статистика и журнал режут теги по `rsplit("@")`. Старое ядро не принимает — запуск повторяется без этого (`_start_core`, до 4 попыток: без adblock.dat, без `process`, без балансировщика).
- **Kill switch** (`kill_switch`): VPN сломался → ядро перезапускается с сервером `Engine.KILL` (blackhole вместо `proxy`), «напрямую» продолжает работать; `_kill_retry` ищет рабочий сервер. Отключение человеком снимает kill switch.
- **История качества:** `_note_quality` (результаты проверок и проверка связи раз в 10 мин; при белых списках неудачи не пишутся), `hour_penalty` — до `HIST_PENALTY` к оценке в «плохие» часы (`_rank_key`).
- **Предупреждения о подписке** — `_sub_alerts` (3 дня, 10% трафика; один раз — `sub_alerts_sent`). **Умные уведомления** — `tell()` → сообщение у значка, если окно закрыто. **VPN на время** — `connect_for`, `_vpn_timer`, `vpn_until`. **Трафик** — `_count_traffic` по дням (`traffic_days`), `traffic_totals`.
- **Пин-код** (`webui.py`): PBKDF2-SHA256 200 000 итераций (`pin_hash`, `pin_salt`), 5 неудач → ожидание 30·2^n с; пока заперто, `dispatch` пропускает только `unlock`/`set_ui`, события не отправляются.

## Zapret и ByeDPI: как устроено

- Настройки: `zapret_enabled`, `zapret_strategy`, `byedpi_role` (`main` / `backup` / `off`), `byedpi_strategy`, `dpi_youtube`, `dpi_discord`, `dpi_custom`, `dpi_update_hours`. Способ обхода в интерфейсе (`DPI_COMBOS` в app.js) — это сочетание `zapret_enabled` и `byedpi_role`.
- Работает **один способ за раз** (`engine.dpi_mode`): `zapret`, `byedpi` или пусто (YouTube и Discord через VPN). Одновременно на одних сайтах они мешают друг другу.
- Маршрут: в «Умной» маршрутизации сайты обхода идут после своих правил пользователя — `direct` (их ускоряет zapret) или в outbound `byedpi` (SOCKS на `127.0.0.1`). В «Глобальной» обход не используется.
- Подбор: `pick_zapret()` / `pick_byedpi()` перебирают стратегии и меряют YouTube/Discord; результат и стратегия для сети (`dpi_networks`) сохраняются.
- Автопереход: `_dpi_watch()` раз в 5 минут; после двух неудач `dpi_failover()`: другая рабочая стратегия → ByeDPI → VPN и жёлтый «!».
- Обновление: `update_dpi()` сверяет номер версии на GitHub и качает, только если вышла новая; работающий winws останавливается перед заменой файлов.
- Тесты: `t_dpi` в selftest запускает настоящий помощник с поддельными `winws`/`ciadpi`.

## Режим TUN: как устроено

- Настройки: `tun_enabled`, `tun_engine` (`auto` / `xray` / `singbox` / `tun2proxy`), `tun_engine_auto` (что заработало в «Авто»), `leak_protection`, `dns_encrypted`, `block_ads`.
- `engine._start_core()` пробует движки по очереди; если ни один не включился — подключается без TUN (системный прокси) и ставит проблему `tun`. Отказ в правах администратора прерывает перебор.
- **Xray TUN:** само ядро запускается через помощника (`ElevatedXray`), во входе `tun` — `autoSystemRoutingTable`, `autoOutboundsInterface: auto` (против петли) и `autoSystemWfpBlockLeak` (защита от утечек). DNS из адаптера (порт 53) → outbound `dns-out` → встроенный DNS ядра.
- **sing-box / tun2proxy:** ядро — обычный процесс, движок через помощника передаёт всё в SOCKS ядра. У sing-box трафик `xray.exe` и `ciadpi.exe` идёт мимо адаптера по имени процесса; у tun2proxy исходящие соединения ядра привязываются к основному адаптеру (`sockopt.interface`).
- ByeDPI в режимах без отбора по процессам привязывается к адресу основного адаптера (`-I`).
- Проверки «без VPN» (сервисы, zapret, пинг) в режиме TUN идут через служебные входы ядра `direct-in` / `direct-http-in`, которые всегда ведут напрямую.
- Тест `t_tun` прогоняет все три движка, «Авто», откат и отказы помощника на поддельных программах.
- `block_quic` (по умолчанию да, только в TUN; на Android — всегда): QUIC внутри TCP-туннеля лагает, браузеры и YouTube при закрытом UDP 443 сразу переходят на TCP.

## Мультисервер, маскировка, белые списки

- **Мультисервер:** `engine.multi_check()` после проверки сервисов (и раз в 3 часа) берёт сервисы, которые через основной сервер (колонка «через VPN») закрыты, и проверяет их через 4 лучших других сервера тем же ядром. Итог — `settings.multi_map` (сервис → ключ сервера); в конфиге это outbounds `multi0…` и правила по доменам сервиса (после своих правил и обхода замедлений). Горячая замена трогает только `proxy` и `proxy~…` (`engine._proxy_tags`).
- **Свои маршруты:** выбор «через VPN / напрямую / блок» хранится в списках `proxy_list` / `direct_list` / `block_list`; «другой сервер / свой прокси / обход замедления» — в `settings.routes` (`"svc:<сервис>"` или `"site:<домен>"` → `{"via": "server"|"custom"|"dpi", ...}`). Свои прокси — `settings.proxies` (`pult/proxies.py`: разбор адреса, подпись без пароля). `engine._route_plan()` превращает `routes` в правила и outbounds: `pinN` — выбранный сервер, `customN` — свой прокси (`xray.custom_proxy_outbound`, «через VPN» = `sockopt.dialerProxy: "proxy"`), обход — `byedpi` или `direct`. Правила стоят сразу после своих списков (сайты раньше сервисов). Недоступный сервер или удалённый прокси → через основной VPN с предупреждением (`_route_target`). Сервисы с ручным выбором пропускают Мультисервер и автоисправление (`_manual_services`). Горячая замена не делается, если к старому или новому серверу привязан маршрут. Пароль прокси никогда не попадает в журнал, `state()` и `share.export`. Тест `t_routes`.
- **Блокировка рекламы:** `pult/adblock.py` качает списки (HaGeZi `*-onlydomains.txt` с jsDelivr и запасным GitHub, AdGuard Russian — только правила `||домен^` без условий) в `data/adblock/`, собирает из них, своих сайтов и исключений один файл `bin/adblock.dat` (формат geosite, тег `ADS`) и подключается правилом `ext:adblock.dat:ads` → outbound `adblock` (blackhole, отдельный от `block` — так журнал отличает рекламу). Нет файла — запасной `geosite:category-ads-all`. Правило стоит после своих маршрутов и списков. **Без VPN:** `engine.start_filter()` поднимает то же ядро с «сервером» `Engine.FILTER` (freedom) — порты, системный прокси, TUN как при VPN, но `connected=False`, `filter_on=True`; `core_running` = VPN или фильтр. `disconnect()` сам включает фильтр, если он нужен (`keep_filter=False` — при обновлении ядра, смене портов, выходе). Монитор поднимает фильтр, если он должен работать, и снимает паузу (`_ads_watch`). Настройки — `set_ads()`, применение — `apply_ads()`. Тест `t_adblock`.
- **Маскировка:** `xray.mask_outbounds(obs, version, variant)`, два способа (`MASK_VARIANTS`: размеры кусочков и паузы). Ядро ≥ 26.10.31 — `streamSettings.finalmask.tcp: [{type: fragment, packets: tlshello}]`; старее — freedom с `fragment` и `sockopt.dialerProxy`. `tester.test_servers(mask_retry=True)` перепроверяет не ответившие серверы сначала способом 1, затем 2 и ставит `result["mask"]` (`True` = 1 или `2`).
- **Белые списки:** `services.whitelist_probe()` (российские разрешённые адреса открываются, зарубежные — нет). `failover()` в этом режиме пробует сначала серверы `is_wl_server()` (по названию или уже проверенные), `test_all()` помечает рабочие `result["whitelist"]`, `_whitelist_watch()` раз в 5 минут ждёт конца ограничений и возвращает к лучшему серверу.
- **Доступ из сети:** входы `lan-socks-in` / `lan-http-in` на `0.0.0.0` со своими портами и, по умолчанию, логином и паролем (`ensure_lan_credentials`); свои входы `127.0.0.1` — без пароля (иначе сломается системный прокси Windows).

## Сборки: как устроено

- `Собрать.bat` (только латиница внутри!) → `build/build-all.ps1` — меню «Windows / Android / всё», журнал каждой сборки в `dist/*-build-log.txt` (Start-Transcript), при ошибке — просьба прислать журнал.
- **APK на компьютере пользователя** — `build/build-android.ps1`: скачивает Temurin JDK 17 (запасной — Microsoft OpenJDK), Android cmdline-tools (номер версии ищется в `repository2-3.xml`, есть запасные), через `sdkmanager` ставит `platforms;android-35`, `build-tools;35.0.0`. Всё лежит в `%LOCALAPPDATA%\VedomyjVPN-build` (или `C:\VedomyjVPN-build`, если в пути есть русские буквы/пробелы — инструменты Android с ними ломаются). Проект копируется туда же (`work\android`, robocopy `/MIR` без `keystore`, `build`, `libs`), там же `GRADLE_USER_HOME`, `TEMP`. Ключ подписи хранится в `…\keystore` и подкладывается в каждую сборку. Если запущен VEDOMYJ VPN (порт из `data/settings.json` или системного прокси), загрузки идут через него: PowerShell — `-Proxy`, Java — `JAVA_TOOL_OPTIONS`. `.bat` (sdkmanager, gradlew) запускаются через `Invoke-Cmd` → `cmd /c "call … 2>&1"`: Windows PowerShell 5.1 иначе считает любой вывод Java в stderr ошибкой. Имена пакетов SDK — **в кавычках** (`"platforms;android-35"`), иначе cmd режет их по `;`. Новые cmdline-tools (2026) сделали `sdkmanager` обёрткой над Android CLI (`--licenses` и прокси-ключи ей не нужны); на всякий случай скрипт сам пишет хэши лицензии в `sdk/licenses/android-sdk-license` — тогда недостающие пакеты докачивает Gradle. Ядро `libv2ray.aar` перекачивается, когда меняется `coreTag` в `app/build.gradle` (метка `libs/libv2ray.version`).
- `build/build.ps1` (Windows). Всё складывается в `dist/`: `VedomyjVPN-<ver>-setup.exe`, `VedomyjVPN-<ver>-portable.zip`, `VedomyjVPN-<ver>-source.zip`. Версия берётся из `pult/__init__.py`.
- **Встроенный Python** — `python-3.13.x-embed-amd64.zip` с python.org (перебор нескольких версий, кэш в `dist/cache`). В файл `python*._pth` дописывается строка `..`, иначе встроенный Python не видит папку программы (папка скрипта в `sys.path` с `._pth` не добавляется).
- **Компилятор** — `csc.exe` из .NET Framework 4, который есть в любом Windows 10/11. Он понимает **только C# 5**: нельзя `$"…"`, `?.`, `nameof`, члены через `=>`. Самопроверка это проверяет. Ключи: `/codepage:65001` (исходники в UTF-8), `/win32icon:ui\icons\app.ico`, `/win32manifest:build\app.manifest`.
- **Установщик** ставит в `%LOCALAPPDATA%\Programs\VedomyjVPN` без прав администратора: закрывает работающую программу (вежливо через `/api/action quit` с токеном из `data/ui.json`, через 10 с — силой и выключает системный прокси, если он указывал на `127.0.0.1`), при обновлении удаляет старые `pult`, `ui`, `python`, распаковывает `app.zip` **не трогая `data/`**, копирует себя как `Uninstall.exe`, создаёт ярлыки (WScript.Shell), пункт в «Приложениях» (`HKCU\…\Uninstall\VedomyjVPN`) и переписывает автозапуск на новый `VedomyjVPN.exe`.
- **Удаление** запускает свою копию из временной папки (`/fromtemp`), убирает автозапуск, ярлыки, пункт «Приложений» и папку программы вместе с `data`.
- Все `build/*.ps1` сохранены в **UTF-8 с BOM** и с переводами строк CRLF: без BOM Windows PowerShell 5.1 читает файл в кодировке ANSI и портит русские имена (`Проверка.bat`). `.bat` — тоже CRLF.
- Сборщики проверены только статически (самопроверка `t_build`); запустить их на Linux нельзя.

| `coretest/run.sh` | **Самопроверка без Android SDK**: сверка с Python-версией (`Dump.java` против `dump.py`), `CoreTest.java` (движок на имитации телефона: подписка → проверка → подключение → Автопереход → белые списки → раздача → свой сервер → перенос), компиляция кода платформы с заглушками SDK (`make_stubs.py`), проход по экранам интерфейса в браузере с настоящим движком (`UiServer.java` + `ui_walk.js`, если есть Node.js и Playwright). |
| `../.github/workflows/android.yml` | Сборка APK в облаке GitHub: ключ из секретов `ANDROID_KEYSTORE`/`ANDROID_KS_PASS` (без них — временный ключ), самопроверка, `assembleRelease`, APK — в Artifacts. Выпуск целиком (ПК + APK + подписанный `latest.json`) — `release.yml`. |

**Две очереди задач (и на Android, и в `pult/engine.py`).** «Подключение» (`lane="conn"` / вид `connect`, `filter`) — подключить, отключить, сменить сервер, применить настройки. «Фон» — всё долгое: проверки, скачивания, подбор zapret/обхода, проверка программы. Очереди идут параллельно, в каждой — одна задача. Фоновая задача ядро сама не перезапускает: на Android просит `applyCore()` (если очередь подключения занята — `pendingApply`, применится сразу после); на ПК замена файлов ядра и перезапуск идут под `_conn_lock` (RLock), поэтому действие человека подождёт секунду и не перепутается. «Остановить» останавливает фоновую задачу (`stop_current` / `stopTask`), отключение — подключение. Монитор на ПК по-прежнему ничего не делает, пока занята любая очередь.

Правила для Android:
1. После изменений — `sh android/coretest/run.sh`, всё должно быть `[OK]`. Новую логику пиши в `core/` и добавляй случай в `CoreTest.java`.
2. Только Java 8 и API, которые есть в Android 8 (никаких `List.of`, `String.repeat`, `var`, записей).
3. Новый метод Android SDK → добавь его сигнатуру в `make_stubs.py`, иначе самопроверка не скомпилирует код.
4. Меняешь разбор ссылок, правила или скрипт сервера в Python — поменяй и в Java (сверка в run.sh это заметит).
5. Проверено только на имитации и в браузере; на настоящем телефоне не запускалось.
6. «Сайт работает не полностью» на телефоне — `Engine.repairSite` (журнал ядра включён всегда, `hostLog`), проверка «качается ли» — `Http.stallTest` (в тестах подменяется `Engine.STALL`). Вопрос «сайт закрыт блокировщиком» — `adsSiteHit` → уведомление через `Engine.Notices`.
7. Необязательные возможности телефона — интерфейсы рядом с `Engine.Platform`: `Notices` (уведомления), `Crypto` (шифрование ключом Android Keystore, `vedomyj_secrets`, AES-GCM; что шифруется — `Engine.SECRET_KEYS`), `NetInfo` (открытый Wi-Fi), `Traffic`, `DeviceInfo`. Реализация — `AndroidPlatform`, в тестах — `CoreTest.Fake`.
8. Свой сервер: состояние и ключи друзей — `Engine.vps*` (`Vps.STATUS_SCRIPT`/`FRIEND_SCRIPT` — те же тексты, что в vps.py, сверка `vpsextra` в run.sh). Пароль вводится для каждого действия и не хранится. Обновление приложения — `core/Update.java` (та же подпись, что update.py) + `ReportProvider` отдаёт `update.apk` установщику. Блокировка приложения — `MainActivity` (`KeyguardManager`, `app_lock`). Виджет — `phone/VpnWidget.java`. «Выключить через 1 ч» — действие `ACTION_HOUR` в уведомлении (`Engine.vpnFor`).
9. Журнал ошибок и сертификаты — как на ПК (см. `core/ErrorLog.java`, `core/Certs.java`); новые настройки — `cert_watch`, `cert_root_ack`, `github_repo` в `Store.defaults()`.
10. Лестница — как `pult/ladder.py`, раздел «лестница самоподбора» в `Engine.java`: `failover()` (сначала белые списки, потом `ladder()`), `probeWays` (временные ядра `XrayConfig.probeConfig` + `dataCheck` через их вход), `Server.fp` и `Server.withWay()`, `netId()` (вид сети + подсеть провайдера из `Proxies.TRACE_URL`), `dataWatch()` по `Engine.Traffic`, `nothingWorks()`. В проверке подменяются `DATA_URL`, `DATA_URLS_MORE`, `WHAT_WORKS`, `SILENT_MS`; имитация в `CoreTest.Fake`: `fpblocked*` (режется отпечаток из `blockedFps`), `empty*` (пинг есть, данных нет).

## Интерфейс: как устроен

- **Страницы** перечислены в `PAGES` (app.js): у каждой есть заголовок и куда ведёт кнопка «Назад». Переход — `go(id)` или кнопка с `data-nav="id"`.
- **«Подробнее»** для любого режима или функции: ключи `i_<id>_name`, `i_<id>_desc` (одна строка), `i_<id>_what`, `i_<id>_when`, `i_<id>_note` в `ui/i18n.js`. Окно открывает `detailModal(id)` (или кнопка с `data-info="id"`), на странице «Функции» те же тексты раскрываются в строке.
- **Функции** — массив `FEATURES` (app.js): `{id, get, set}` для переключателя или `{id, nav}` для кнопки «Настроить». То, чего ещё нет, перечислено в `SOON` — такие пункты видны с пометкой «скоро» и не включаются. Когда функция появится, убери её id из `SOON` и добавь `get/set`.
- **Выпадающие списки** — `openDropdown(anchor, groups, onPick)`: пункты как в Happ, у каждого «Подробнее».
- **Тексты**: каждый ключ должен быть в обоих словарях `STRINGS.ru` и `STRINGS.en`.
- **Ничего не должно сдвигать страницу.** Плашка «Подключаюсь…» (`#busy`) плавает внизу слева, а не встаёт под шапкой (раньше из-за неё прыгала круглая кнопка). Всё, что появляется и исчезает, — поверх или в заранее занятом месте.
- **Журнал** хранит исходные строки (по-русски), переводит при показе: `engine.logs_view()`.

## Частые задачи

- **Добавить сервис в проверку:** `pult/services.py` → `SERVICES` (адреса для проверки и домены для маршрутов).
- **Добавить заблокированный сайт во встроенный список:** `pult/routing.py` → `BUILTIN_PROXY_DOMAINS`.
- **Добавить российский сервис «всегда напрямую»:** `pult/routing.py` → `RU_DIRECT_DOMAINS`.

- **Новый формат ссылок:** парсер в `pult/links.py` (`PARSERS`) + тест в `selftest.py`.

## Обход ограничений сети

- **Защищённый DNS:** `netutil.DOH_SERVERS` — DoH по RFC 8484 (`dns_query`/`dns_answers`, ответ кэшируется 10 мин), к сервису подключаемся по IP с проверкой сертификата по имени (`http_get(pin=…)`). Android: `Http.DOH_SERVERS`, `dnsQuery`/`dnsAnswers` (сверка с Python — `Dump dns` в run.sh).
- **Свои загрузки** (`download_file`, `http_get(doh=True)`, Android `Http.downloadTo`/`requestOwn`): если DNS провайдера не знает адрес — сами берут его из защищённого DNS (и после перенаправлений). Проверки сайтов так НЕ делают: им нужно видеть блокировку.
- **Любым путём:** `Engine._fetch_any(job, что)` — через VPN, напрямую, через другие серверы (`_relay`, временное ядро, `relay.json` стирается); неудача другого пути запоминается на 2 мин. Android: `Engine.downloadAny`. Списки сайтов — с запасных адресов (`xray.GEO_MIRRORS`, Android `GEO_MIRRORS`); версия ядра — со страницы выпуска, если API GitHub не ответил (`netutil.final_url`).
- **Имя сервера заблокировано в DNS:** `Engine._pin_server_dns` (перед проверкой и подключением; раз в 10 мин на имя) → `Server.pinned_ip` → `xray.pin_address` (адрес — IP, имя — в SNI/Host/authority). Android: `pinServerDns`, `XrayConfig.pinAddress`.
- **Подписка:** ответ «от провайдера» (`PROVIDER_HEADERS` или серверы) останавливает поиск; заглушка провайдера интернета (`BLOCK_PAGE_MARKS`) и пустые ответы — нет.
- **Страница входа Wi-Fi:** `netutil.captive_portal()` в `_net_watch` (Android — `NET_CAPABILITY_CAPTIVE_PORTAL` в `netInfo`): пока не вошли — без «всё через VPN» и kill switch.
- **Часы:** `netutil.clock_skew()` раз в час → «!» `clock` (Android — `clockCheck`, раз в 6 ч). **Антивирус:** `xray.start_error`, пропавшее ядро после `xray_seen`.

## Проверка на настоящем компьютере и телефоне

`field_check.py` и «Проверка новых функций.bat» (ПК) и «Настройки → Проверка программы» (телефон) проверяют то, что в самопроверке только имитируется: настоящее ядро Xray принимает новые настройки, DPAPI, горячую клавишу, разбор netsh, замирание соединений, утечки, подпись выпуска. Отчёт без ссылок, ключей и адресов — его можно присылать нейросети. `field_check.py --ci` — то же на Windows в облаке GitHub (`.github/workflows/windows.yml`): сам скачивает ядра Xray и sing-box кодом программы, проверяет движки (`check_engines`: Hysteria2, запасной Hysteria2, TUIC через мост; `check_singbox`: мост TUIC/AnyTLS), включает и выключает настоящий туннель AmneziaWG (`check_awg`, только сеть 10.250.0.0/24, клиент ставится шагом workflow из выпуска amneziawg-windows-client), пропускает проверки сети провайдера, код выхода 1 при ошибках, отчёт — в Artifacts.

## Известные ограничения

- Hysteria2, TUIC и WireGuard-ссылки не поддерживаются (пропускаются с пояснением).
- Режим TUN, значок у часов и раздача по Wi-Fi проверены только на имитации; на настоящем Windows возможны особенности (zapret видит и пакеты адаптера TUN; раздача с адаптера TUN зависит от того, считает ли Windows его подключением к интернету).
- ByeDPI помогает только программам, которые идут через системный прокси; приложению Discord нужен zapret.
- Zapret и ByeDPI работают только в Windows.
- Подписки в форматах Clash/sing-box не читаются — программа просит у сервера обычный формат.
